## ٢. الحماية حسب المكوّن

**قاعدة البيانات:** SQLAlchemy ORM بس — مفيش ولا سلسلة SQL مبنية يدوياً.
المفاتيح الأجنبية حقيقية ومفعّلة، فمفيش سجل يتخلق من غير مؤسسة صحيحة.

**الجلسات:** JWT موقّع بـ `APP_SECRET_KEY`. التوكن فيه `sub` + `org_id` + `role`،
فالصلاحيات بتتأكد على مستوى كل طلب مش على مستوى الواجهة.

**المفاتيح السرية:** مفيش أي مفتاح في الكود. كلهم من البيئة (`.env`) أو من
قاعدة البيانات (متشفّرين).

**النشر:** المهام الخلفية بتشتغل بحساب `realign` مش `root`.
ملف systemd فيه `NoNewPrivileges` و`ProtectSystem=strict`.

## ٣-مكرر. اللي **مش** موجود (وليه)

| الناقص | البديل دلوقتي | إمتى تزوده |
|---|---|---|
| التحقّق بخطوتين (2FA) | كلمة سر قوية + جلسة قصيرة + قفل تلقائي | قبل أول عميل مؤسسي كبير |
| SSO / SAML | تسجيل داخلي بالدعوات | لما تبيع لشركات كبيرة |
| تشفير على مستوى الأقراص | تشفير على مستوى الحقول (Fernet) | على السيرفر (LUKS/dm-crypt) |
| WAF وشبكة DDoS | تحديد معدّل على مستوى التطبيق | حافة الاستضافة (Railway) تكفي للانطلاق |
| سجل تدقيق غير قابل للتعديل | append-only في الكود | انقله لخدمة WORM لما تكبر |
| مراقبة ٢٤/٧ | فحص `/api/v1/health` | خدمة خارجية (UptimeRobot مجاني) |

## ٤. قائمة تحقّق قبل الاستضافة العلنية

**اللي بيتظبط تلقائياً في `production`:** إجبار HTTPS · HSTS · CSRF · كوكيز `Secure` ·
تحديد المعدّل · إخفاء `/docs` · CORS بقيود · ترقية الهجرات في Docker.
**الإنتاج يرفض الإقلاع أصلاً** لو أي واحد منهم معطّل.

- [ ] `APP_ENV=production` و`DEBUG=false`
- [ ] `APP_SECRET_KEY` متولّد عشوائي (مش الافتراضي)
- [ ] `CREDENTIALS_ENCRYPTION_KEY` متولّد ومحفوظ في مكان آمن خارج السيرفر
- [ ] `DATABASE_URL` على PostgreSQL (مش SQLite)
- [ ] HTTPS مفعّل (Certbot / شهادة مجانية)
- [ ] الكوكيز عليها `Secure` (تلقائي في production)
- [ ] `ALLOW_PUBLIC_SIGNUP` مقفول لو مش عايز تسجيل مفتوح
- [ ] نسخ احتياطي يومي شغال (`scripts/backup.sh` في cron)
- [ ] `WORKER_ENABLED=true` و`SCHEDULER_ENABLED=true`
- [ ] مراقبة `/api/v1/health` كل دقيقة
- [ ] اللوج بيتجمّع في مكان بيحتفظ بيه (`LOG_JSON=true`)
